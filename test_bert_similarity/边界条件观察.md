> 基于 `验证输出/1.5B_epoch5_hislen8_test_v2*.json`（200 条）与 `学习轨迹/WebShop_test_seed_42_*.json`（200 条）的对比分析

## 一、词集相同 search 动作占比

> **统计方法**：与 `rollout_loop_parallel_webshop.py` 中的 `extract_think_and_actions` 函数完全一致
> - 每条 assistant 消息初始化 5 个环境动作为 `"null"`
> - 从 `<env_i>...</env_i>` 标签中提取动作，仅填充 `1~5` 范围内的合法 env_index
> - `null`/`None`/空动作保持为 `"null"`
> - 因此 `search + click + null + other = assistant消息数 × 5` **恒等成立**
>
> **完整性验证**：
> - 验证输出：assistant 2,386 条 × 5 = **11,930** 个动作 slot，实际 search+click+null+other = **11,930**（差异 0）
> - 学习轨迹：assistant 2,635 条 × 5 = **13,175** 个动作 slot，实际 search+click+null+other = **13,175**（差异 0）

### 1.1 动作计数（与代码一致）

| 动作类型 | 验证输出 (200条) | 学习轨迹 (200条) |
|---|---|---|
| search 动作数 | 4,980 | 7,679 |
| click 动作数 | 6,336 | 4,824 |
| null 动作数 | 613 | 667 |
| other（异常格式） | 1 | 5 |
| **总计（=assistant×5）** | **11,930** | **13,175** |

### 1.2 search 重复分析（仅 search 动作）

| 指标 | 验证输出 (200条) | 学习轨迹 (200条) |
|---|---|---|
| 唯一 search 文本数 | 4,430 | 7,352 |
| 唯一词集数 | 3,671 | 6,262 |

### 1.3 词集相同的 search 动作分类

| 类型 | 验证输出 | 学习轨迹 |
|---|---|---|
| **精确重复**（文本完全相同） | 550 条（11.0%） | 327 条（4.3%） |
| **词序重排**（词集相同、文本不同） | 1,096 条（22.0%） | 1,290 条（16.8%） |
| **词集相同总计** | **1,646 条（33.1%）** | **1,617 条（21.1%）** |

### 1.4 关键发现

1. **词集相同的 search 动作占比高**：验证输出 33.1%、学习轨迹 21.1%，即两到三成的 search 动作可通过词集匹配捕获
2. **词序重排远多于精确重复**：
   - 验证输出：词序重排（22.0%）是精确重复（11.0%）的 2.0 倍
   - 学习轨迹：词序重排（16.8%）是精确重复（4.3%）的 3.9 倍
3. **验证输出的重复更严重**：词集相同占比 33.1% vs 21.1%，精确重复占比 11.0% vs 4.3%
4. **方案 E 的价值**：词集匹配可确定性捕获 21.1%~33.1% 的 search 动作，无需依赖嵌入模型的词序稳定性

## 五、结论

### 5.1 阈值 0.975 已到纯嵌入方案极限

- 0 误检，但上方裕度极薄（9 个样本在阈值上方 0.005 以内）
- 9 个词集相同的词序重排漏检无法通过调阈值解决（降阈值会引入误检）
- 非衬衫类（家具、鞋类、食品）同样存在词序不稳定问题

### 5.2 方案 E（词集匹配兜底）必须实施

- 词集匹配可确定性捕获 21.1%~33.1% 的 search 动作
- 极端案例：单个词集产生 43 次冗余搜索、23 种排列，精确匹配只能识别其中约一半
- 词集匹配不受嵌入模型非确定性影响，将词序重排从嵌入区间移除后，阈值 0.975 只需处理真正的语义近似

### 5.3 验证输出与学习轨迹有明显区别

- 模型推理时 search 减少 10%、click 增加 11%，探索性不足
- 精确重复率（51.2%）显著高于训练数据（43.3%）
- 长轨迹性质相反：训练数据是有效探索（重复率 25.8%），模型是卡住循环（重复率 51.9%）
