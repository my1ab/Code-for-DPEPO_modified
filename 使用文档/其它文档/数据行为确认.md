# 数据行为确认：官方 verl-agent vs 本地 quick_start.md 第 1 章

> 核对对象：官方 GitHub `langfengQ/verl-agent`（master）README 中的 WebShop & Search 配置说明，与本地 `使用文档/quick_start.md` 第 1 章（1.1–1.5.2）的安装指令。
> **核对口径：仅参考文档第一章的安装指令本身，不考虑本地已存在文件/代码状态**（不参考本地预生成索引、本地 `utils.py` 改动等）。
> 核对范围：仅数据行为（下载、建立索引、合并、解压、启动检索服务器等），不核对 pack 安装。
> **最终结论：数据行为一致 ✅**

---

## 一、官方 verl-agent 的 WebShop & Search 数据行为

### 1. WebShop（`./setup.sh -d all`，在 `agent_system/environments/env_package/webshop/webshop/` 下）

**① 数据集下载（gdown → 仓库内 `webshop/webshop/data/`）**，共 5 个文件：

| 文件 | 说明 | 下载条件 |
|------|------|---------|
| `items_shuffle_1000.json` | 1000 商品 scraped 信息 | small / all |
| `items_ins_v2_1000.json` | 1000 商品属性 | small / all |
| `items_shuffle.json` | 全量商品 scraped 信息 | 仅 all |
| `items_ins_v2.json` | 全量商品属性 | 仅 all |
| `items_human_ins.json` | 人类指令数据 | 始终 |

- 官方注明：gdown 失败需 Google Drive cookie（`.cache/gdown/cookies.txt`）或手动下载。

**② spaCy 模型下载**：`python -m spacy download en_core_web_lg`、`en_core_web_sm`（verl-agent 版本两者都装）。

**③ 建立 Lucene 检索索引**（`webshop/search_engine/` 下）：
1. `mkdir -p resources resources_100 resources_1k resources_100k`
2. `python convert_product_file_format.py` — 经 `web_agent_site/utils.py` 的 `DEFAULT_FILE_PATH=../data/items_shuffle_1000.json` 读取商品，生成 `resources*/documents.jsonl` 四档（100 / 全量 / 1k / 100k）
3. `mkdir -p indexes && ./run_indexing.sh` — pyserini Lucene 建 `indexes_100`、`indexes`、`indexes_1k`、`indexes_100k`

（human trajectories 下载在 verl-agent 版本已注释，princeton 原版会下到 `user_session_logs/`）

### 2. Search（README "3. Search"）

**① 预处理数据集**：`python examples/data_preprocess/preprocess_search_r1_dataset.py`
- 从 HF `PeterJinGo/nq_hotpotqa_train` 下载 `train.parquet` / `test.parquet` → 处理 → 存 `~/data/searchR1_processed_direct/`

**② 下载检索索引**（独立 `retriever` 环境，Python 3.10）：
- `python examples/search/searchr1_download.py --local_dir ~/data/searchR1`
  - 从 HF `PeterJinGo/wiki-18-e5-index` 下载 `part_aa`、`part_ab`
  - 从 HF `PeterJinGo/wiki-18-corpus` 下载 `wiki-18.jsonl.gz`
- `cat $local_dir/part_* > $local_dir/e5_Flat.index`（合并分片）
- `gzip -d $local_dir/wiki-18.jsonl.gz`（解压 18GB 语料）

**③ 启动检索服务器**：`bash examples/search/retriever/retrieval_launch.sh > retrieval_server.log`
- 前台运行，`--faiss_gpu --port 8000`，加载 `~/data/searchR1/{e5_Flat.index, wiki-18.jsonl}`，模型 `intfloat/e5-base-v2`，topk 3

## 二、文档第一章安装指令 vs 官方数据行为对照（仅按指令，不考虑本地已有文件）

| 环节 | 官方 README/脚本指令 | 文档第一章指令 | 数据行为 |
|------|---------------------|--------------|---------|
| WebShop 数据下载 | gdown 下载 5 个文件（Google Drive） | ModelScope 下载同名 5 个文件到 `~/data/` | ✅ 文件清单一致 |
| WebShop 建索引 | `mkdir resources*` → `convert_product_file_format.py` → `mkdir indexes` → `run_indexing.sh` | 相同流程（1.4.1 Step 0–2，手动执行） | ✅ 一致 |
| Search 预处理 | `preprocess_search_r1_dataset.py` → `~/data/searchR1_processed_direct` | 同脚本 → 同目录（加 `HF_ENDPOINT` 镜像） | ✅ 一致 |
| Search 索引下载/合并/解压 | `searchr1_download.py` → `cat part_* > e5_Flat.index` → `gzip -d wiki-18.jsonl.gz` | 同（Step 1–2） | ✅ 一致 |
| 检索服务器 | `retrieval_launch.sh`：端口 **8000**、前台、输出重定向 | `retrieval_launch_faiss.sh`：端口 **8010**、nohup 后台、就绪信号轮询、faiss_gpu 分片加载 | ✅ 数据加载一致（e5_Flat.index + wiki-18.jsonl + faiss_gpu + topk 3）；端口/启动方式不同 |

### 非数据本质差异（不影响数据行为一致性）

| # | 环节 | 官方 | 文档第一章指令 | 说明 |
|---|------|------|--------------|------|
| 1 | WebShop 下载渠道 | gdown（Google Drive，需代理/cookie） | ModelScope 定向下载 | 文件清单相同，渠道不同 |
| 2 | 检索服务器端口 | 8000 | 8010 | 端口不同（训练脚本以 `SEARCH_PORT=8010` 连接，与文档一致） |
| 3 | 检索服务器启动方式 | 前台运行 | nohup 后台 + 就绪信号自动退出 | 数据加载行为不变 |
| 4 | Search 预处理网络 | 直连 HF | `HF_ENDPOINT=https://hf-mirror.com` | 网络适配，下载内容不变 |
| 5 | 环境 | 独立 `verl-agent-webshop`（Py3.10）+ `retriever`（Py3.10） | 统一 `verl_train_2`（Py3.11，检索包已集成） | 环境合并，数据行为不变 |

---

## 三、最终结论

**数据行为一致。** 文档第一章的安装指令与官方 verl-agent 的数据行为（下载文件清单、索引构建流程、分片合并、解压、数据加载）完全对应，仅存在渠道（gdown→ModelScope/HF 镜像）、端口（8000→8010）、启动方式（前台→后台）、环境（独立→合并）等非数据本质差异，不影响数据行为一致性。
