## 1. Prompt 模板

### 1.1 `agent_system/multi_turn_rollout/prompts_search.py`（新增）

为 Search 任务设计并行探索 prompt 模板，包含三个核心模板：

- **`SYSTEM_PROMPT_SEARCH_PARA`**：系统 prompt，说明多环境并行探索规则、`<parallel>`/`<env_i>` 标签格式、`<search>`/`<answer>` 两种动作类型
- **`USER_PROMPT_NO_HIS_PARA`**：首轮 user prompt（无历史），包含 question + 各环境 `<observation_i>` 标签
- **`USER_PROMPT_HIS_PARA`**：后续轮 user prompt（含历史），包含 task_description + initial_observation + history_info + last_history

与原始 Search-R1 单环境 prompt 的主要差异：
- 单环境 `<search>`/`<answer>` → 多环境 `<parallel><env_i><search>...</search></env_i></parallel>`
- 新增并行探索规则（环境选择、null 动作、环境切换）
- 历史格式从 `<search>`/`<information>` XML 标签 → 纯文本 "In Environment i: Action/Observation"

### 1.2 `agent_system/multi_turn_rollout/prompts_webshop.py`（修改）

为 WebShop 任务设计并行探索 prompt 模板：

- **`system_message_para`**：系统 prompt，说明多环境并行探索规则、`search[...]`/`click[...]` 动作格式
- **`reason_prompt_para`**：首轮 user prompt（无历史）
- **`reason_prompt_para_his`**：后续轮 user prompt（含历史）

与原始 WebShop 单环境 prompt 的主要差异：
- 单环境 `search`/`click` → 多环境 `<parallel><env_i>action</env_i></parallel>`
- 新增并行探索规则、null 动作处理、环境切换策略

## 2. Rollout 循环

### 2.1 `agent_system/multi_turn_rollout/rollout_loop_parallel_search.py`（新增）

`TrajectoryCollectorParallelSearch` 类，Search 任务的并行多轮 rollout 循环。主要新增内容：

- **`extract_think_and_actions`**：从模型输出中提取 `<think>` 内容和 `<env_i>` 标签内的动作，未匹配环境自动填充 "null"
- **`preprocess_single_sample`/`preprocess_batch`**：构建多环境并行输入，step==0 使用无历史 prompt，step>0 使用带历史 prompt，支持 `history_length` 截断
- **`calculate_penalties`**：四维多样性惩罚计算（深度重复 / 深度转移 / 宽度转移 / 宽度重复），支持嵌入相似度与精确匹配双模式
- **`calculate_depth_repeat`/`calculate_transition_repeat`/`_calculate_width_repeat_weighted`**：各维度重复计数，通过 `USE_EMBEDDING_SIMILARITY` 全局开关切换精确匹配 / 嵌入加权
- **`calculate_process_reward`**：基于 LCS 的过程奖励，取并行环境中最大匹配值
- **`vanilla_multi_turn_loop`**：主循环，包含 active mask 优化（跳过已完成样本推理）、null 连续计数提前终止、轨迹保存
- **`_ensure_embedding_manager`**：嵌入模型延迟初始化（首次调用时加载，单例模式）

### 2.2 `agent_system/multi_turn_rollout/rollout_loop_parallel_webshop.py`（修改）

`TrajectoryCollectorParallelWebShop` 类，结构与 Search 版本一致，差异：
- 使用 `prompts_webshop.py` 模板（`system_message_para`/`reason_prompt_para`/`reason_prompt_para_his`）
- task 字段从 `[SEP]` 格式提取（而非直接用 question）
- Observation 包含 `available_actions`（`has_search_bar` + `clickables`）
- 动作格式为 `search[...]`/`click[...]`（方括号格式）
- 同样集成了 `calculate_penalties` 四维惩罚和嵌入相似度支持

### 2.3 `agent_system/multi_turn_rollout/rollout_loop_parallel.py`（修改）

ALFWorld 任务的并行 rollout 循环（原始 verl-agent 已有），项目中对齐了接口风格。

## 3. 环境管理器

### 3.1 `agent_system/environments/env_manager_parallel_search.py`（新增）

Search 任务的并行环境管理器。主要新增内容：
- 多环境副本管理（`num_parallel` 个独立 Search 环境）
- `get_start_info_group`/`step_group`/`get_history_info_group`/`get_last_actions_info_group`：批量接口，返回按环境 1-based 索引的字典

- 检索服务器通过 `SEARCH_PORT`/`SEARCH_URL` 环境变量连接

- 批量接口与 Search 版本对齐

## 4. 嵌入相似度模块

### 4.1 `agent_system/multi_turn_rollout/emb.py`（新增）

`EmbeddingManager` 类，将多样性惩罚中的精确字符串匹配替换为语义相似度加权计数。

**核心设计**：
- **单例模式**：`__new__` 实现单例，全进程共享一个嵌入模型实例
- **本地加载**：`local_files_only=True`，禁止远端下载，路径校验失败直接 `raise RuntimeError`
- **CPU 推理**：默认 CPU 推理（绕过 Ray actor GPU 可见性问题），支持 `EMBEDDING_DEVICE` 环境变量切换 GPU
- **CLS pooling + 归一化**：与 bge-large-en-v1.5 官方用法一致
- **嵌入缓存**：`_cache` 字典缓存已计算过的文本向量，避免重复推理

**分类型相似度策略**（通过 `task_type` 参数选择）：
- **`_webshop_task_handler`**（task_type='webshop'）：
  - `click[...]`：大小写不敏感精确匹配，返回 0.0 或 1.0
  - `search[...]`：词集匹配优先（方案 E），嵌入兜底 + 线性放大（方案 B）
  - 跨类型 / null：返回 0.0 / 1.0
- **`_search_task_handler`**（task_type='search'）：
  - `<search>...</search>`：词集匹配优先，嵌入兜底 + 线性放大
  - `<answer>...</answer>`：完全匹配（已统一小写），返回 0.0 或 1.0
  - 跨类型 / null：返回 0.0 / 1.0

**关键方法**：
- `weighted_match(action_a, action_b)`：加权匹配，返回 [0, 1] 的相似度值，供 `calculate_penalties` 使用
- `_text_content_similarity`：search 文本的词集匹配 + 嵌入兜底 + 线性放大 `(sim - threshold) / (1 - threshold)`
- `_parse_action`：统一解析方括号格式（WebShop）和尖括号格式（Search）的动作字符串
- `raw_similarity`：返回未过滤的原始余弦相似度，用于测试与日志

## 5. 训练入口

### 5.1 `train_scrips/for_search/main_ppo_search.py`（新增）

Search 任务的 PPO/GRPO 训练入口，基于 verl-agent 原始 `main_ppo.py` 修改。主要修改内容：

- **Hydra 配置**：`config_name` 改为 `ppo_trainer_parallel`（原为 `ppo_trainer_webshop`）
- **环境构建**：调用 `build_parallel_search_envs`（原为 `build_parallel_envs`），传入 `num_parallel` 参数
- **gamefile 加载**：从训练 parquet 的 `gamefile` 列读取（int 类型 physical_idx），而非从 `env_path` JSON 读取
- **SOURCE_PARQUET**：新增 `_DPEPO_USER_HOME/data/searchR1_processed_direct/train.parquet` 路径，通过 `iloc[int]` 将 physical_idx 解析为 question + ground_truth
- **search_env_config**：从 `config.env.search.*` 提取 `search_url`/`topk`/`timeout`/`log_requests`/`max_turns`，作为 `env_kwargs` 传入环境构建
- **lazy_envs 支持**：`lazy_envs=True` 时返回 `_build_search_envs` 闭包（延迟创建），`False` 时立即创建
- **TrajectoryCollector**：实例化 `TrajectoryCollectorParallelSearch`（原为 `TrajectoryCollector`）
- **Ray init**：新增 `CUDA_VISIBLE_DEVICES` 传递到 Ray runtime_env（Search 独有，确保 GPU 可见性）
- **计时日志**：新增 `main()` 执行时间统计

### 5.2 `train_scrips/for_webshop/main_ppo_webshop.py`（新增）

WebShop 任务的 PPO/GRPO 训练入口，基于 verl-agent 原始 `main_ppo.py` 修改。主要修改内容：

- **Hydra 配置**：`config_name` 改为 `ppo_trainer_parallel`
- **环境构建**：调用 `build_parallel_webshop_envs`（原为 `build_parallel_envs`），传入 `num_parallel` 参数
- **gamefile 加载**：从 `config.env.env_path` JSON 文件读取（保持原方式，与 Search 不同）
- **lazy_envs 支持**：`lazy_envs=True` 时返回 `build_parallel_webshop_envs` 函数引用（延迟创建），`False` 时立即创建
- **TrajectoryCollector**：实例化 `TrajectoryCollectorParallelWebShop`（原为 `TrajectoryCollector`）
- **计时日志**：新增 `main()` 执行时间统计

### 5.3 Search vs WebShop 训练入口差异

| 差异点 | `main_ppo_search.py` | `main_ppo_webshop.py` |
|--------|----------------------|----------------------|
| 环境构建函数 | `build_parallel_search_envs` | `build_parallel_webshop_envs` |
| gamefile 来源 | parquet `gamefile` 列（int physical_idx） | `env_path` JSON 文件 |
| 额外 env_kwargs | `parquet_path` + `search_url`/`topk`/`timeout` 等 | 无 |
| SOURCE_PARQUET | `~/data/searchR1_processed_direct/train.parquet` | 无 |
| Ray CUDA_VISIBLE_DEVICES | 传递（Search 独有） | 不传递 |
| TrajectoryCollector | `TrajectoryCollectorParallelSearch` | `TrajectoryCollectorParallelWebShop` |

## 6. 训练脚本

### 6.1 `train_scrips/for_search/`（新增）

Search 任务训练脚本集：
- `main_ppo_search.py`：训练入口，调用 `TrajectoryCollectorParallelSearch`
- `eval_similarity_bs4/`：主流实验组（bs=4, tp=2），含 emb 0.8/0.9 + no_emb + lr 扫描
- `eval_similarity_bs1/`：完整阈值扫描（emb 0.5~0.9）
- `eval_similarity_resume/`：续训脚本（从 step 500 merged checkpoint）
- `config/ppo_trainer_parallel.yaml`：默认配置

### 6.2 `train_scrips/for_webshop/`（新增）

WebShop 任务训练脚本集：
- `main_ppo_webshop.py`：训练入口，调用 `TrajectoryCollectorParallelWebShop`
- `eval_similarity_bs4/`：主流实验组（bs=4, tp=2），含 emb 0.8/0.9 + no_emb
- `config/ppo_trainer_parallel.yaml`：默认配置

### 6.3 脚本统一设计

所有训练脚本共享以下设计：
- **路径变量**：顶部 `DPEPO_USER_HOME`/`DPEPO_PROJECT_NAME` 统一配置
- **嵌入参数**：`+custom.use_embedding`/`+custom.emb_threshold` 通过 Hydra 注入 config
- **后台运行**：`nohup ... &` + `tail -F` 自动跟踪日志
- **LoRA + FSDP offload**：`param_offload`/`optimizer_offload` 降低显存占用
- **vLLM rollout**：`enforce_eager`/`free_cache_engine` 控制 vLLM 缓存释放

### 6.4 `train_scrips/install/install_verl_train.sh`（新增）

一键安装脚本，11 步完成 `verl_train_2` 环境搭建（PyTorch / vLLM / FlashAttention / Ray / Agent 环境等），安装后自动验证。
