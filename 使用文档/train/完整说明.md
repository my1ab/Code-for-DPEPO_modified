### 2.5 Parquet 结构与 main_ppo 读取逻辑

#### 2.5.1 Parquet 字段说明

所有任务（WebShop / Search / ALFWorld）的训练 parquet 均包含以下字段，由 `prepare_*_parquet.py` 脚本生成：

| 字段 | 类型 | 是否必需 | 说明 |
|------|------|---------|------|
| `gamefile` | int | **✅ 必需** | 环境查找的 key。WebShop 中为 goal index (600~6909)，Search 中为 source parquet 的 physical_idx |
| `prompt` | list[dict] | ⚠️ 占位符 | 内容为 `[{'role': 'user', 'content': 'The prompt is dynamic obtained from envs'}]`。会被 rollout loop 中动态构建的 prompt 完全覆盖 |
| `data_source` | str | ⚠️ 仅 debug | 内容为任务名 (`webshop` / `search`)。仅用于奖励管理器的 debug print |
| `answer` | str | ❌ 无用 | 空字符串，从未被读取 |
| `ability` | str | ❌ 无用 | 固定为 `'agent'`，从未被读取 |
| `extra_info` | dict | ❌ 无用 | 包含 `split` 字段，从未被读取 |

**核心结论：`gamefile` 是唯一真正影响训练流程的字段，其余字段均为占位符或调试信息。**

#### 2.5.2 三种任务的读取逻辑对比

| 任务 | main_ppo 入口 | `gamefile` 含义 | 非 lazy 时环境构建数据源 | lazy 时环境构建数据源 |
|------|-------------|----------------|------------------------|---------------------|
| **WebShop** | `main_ppo_webshop.py` | goal index (600~6909 或 0~499) | **JSON** (`env.env_path`) → `list(data.values())` | **Parquet** (dataloader `non_tensor_batch['gamefile']`) |
| **Search** | `main_ppo_search.py` | physical_idx (source parquet 行号) | **JSON** (`env.env_path`) → `list(data.values())` | **Parquet** (dataloader `non_tensor_batch['gamefile']`) |
| **ALFWorld** | `main_ppo_alfworld.py` | goal index | **JSON** (`env.env_path`) → `list(data.values())` | **Parquet** (dataloader `non_tensor_batch['gamefile']`) |

**关键代码对比**：

```python
# 所有任务统一从 JSON 读取 gamefiles（非 lazy 模式）
data = json.load(open(config.env.env_path, "r"))
gamefiles = list(data.values())            # 或 [item["gamefile"] for item in data]
```

> 注意：Search 任务在早期版本中曾从 Parquet 读取 gamefiles，现已统一为与 WebShop/ALFWorld 一致，从 JSON 读取。

**lazy 与非 lazy 的核心区别**：

```
lazy_envs=false:
    main_ppo 中:  gamefiles 从 JSON 读取 → 一次性创建所有环境
    ray_trainer:  直接使用 main_ppo 传入的 envs (self.envs 保持不变)

lazy_envs=true:
    main_ppo 中:  只存 build_env_func 函数引用, envs = None
    ray_trainer:  每步从 batch.non_tensor_batch['gamefile'] 取当前 batch 的 gamefile
                  → 按 batch 动态创建环境 → 用完即弃
```

**关键影响**：当 `lazy_envs=true` 时，所有任务（WebShop / Search / ALFWorld）的 JSON 文件**不再参与环境构建**，环境构建完全依赖 Parquet 的 `gamefile` 列，通过 dataloader 的 `non_tensor_batch['gamefile']` 按 batch 动态获取。

#### 2.5.3 lazy_envs 模式的影响

`lazy_envs` 控制环境是**一次性全部创建**还是**按 batch 动态创建**：

```
lazy_envs=false (默认):
    main_ppo 中:
        gamefiles = 全部 500 个 gamefile (从 JSON 读取)
        envs = build_*_envs(gamefiles=gamefiles)  ← 一次性创建 500 个环境
        val_envs = None
    ray_trainer.fit():
        self.envs 保持不变，直接传给 traj_collector

lazy_envs=true:
    main_ppo 中:
        build_env_func = build_*_envs             ← 只存函数引用
        envs = None, val_envs = None
    ray_trainer.fit():
        for batch in dataloader:
            current_step_gamefiles = batch.non_tensor_batch['gamefile']  ← 从 dataloader (Parquet) 取
            self.envs = build_env_func(gamefiles=current_step_gamefiles)  ← 只建当前 batch
            traj_collector.multi_turn_loop(envs=self.envs, ...)
    _validate():
        self.val_envs = build_env_func(gamefiles=current_step_gamefiles)  ← 验证也按 batch 重建
```

**无论 lazy 与否，核心机制相同**：`gamefile` (int) 作为唯一 ID，通过 `workers_dict[gamefile]` 找到对应 Ray worker。区别仅在于 Ray worker 的创建时机。

## 6. 常见问题（FAQ）

### 6.1 检索服务器连接失败（仅 Search 任务）

- 训练前需先启动检索服务器（见 1.4.2 Step 3 / 4.2，使用 `retrieval_launch_faiss.sh`），启动后可用 `curl "http://127.0.0.1:8010/retrieve"` 验证服务是否就绪。
- ⚠️ **`Ctrl+C` 退出启动脚本可能导致检索服务器一并终止**。退出后请用 `curl` 验证服务是否存活；若已终止需重新启动，或改用 `nohup` 方式使服务器脱离终端。
- 若端口被占用：`lsof -i :8010` 查看占用进程，杀掉占用进程，或更换端口（需同步修改 `retrieval_launch_faiss.sh` 中的 `PORT` 与训练脚本中的 `SEARCH_PORT`）。
- 日志出现 `Connection refused` / `Failed to retrieve` 等错误，通常是检索服务器未启动，或在错误环境启动（应使用集成环境 `verl_train_2`，无需单独创建 retriever 环境）。

### 6.2 显存不足（OOM）

- 将 `gpu_memory_utilization` 从 `0.3` 调低至 `0.2`（见 3.1.4）。
- 降低 `batchsize` / `micro_para`，或改用单卡脚本（见 3.1.2）。
- 确认已设置 `VLLM_ATTENTION_BACKEND=FLASH_ATTN`。

### 6.3 模型路径错误（找不到 checkpoint / BGE 模型）

- `actor_rollout_ref.model.path` 必须指向实际存在的 checkpoint 完整路径（见 1.5.1），若下载到自定义目录需同步修改。
- BGE 嵌入模型需提前下载到 `emb_models/bge-large-en-v1.5`（见 1.5.2）；训练时 `local_files_only=True`，模型缺失会直接报错终止。

### 6.4 数据文件缺失（JSON / Parquet 找不到）

- 确认 `~/data/` 目录结构与 1.4.3 完全一致。
- 确认已运行数据准备脚本（见 2.1 / 2.2），生成的文件名与训练脚本路径（3.2.2 / 3.3.2）一致；WebShop 的 `EXCLUDE_SUCCESS` 必须保持 `True`，否则不会生成 `_excluded` 文件。

### 6.5 训练启动后立即退出

- 查看启动脚本打印的日志路径：`tail -f <日志路径>`。
- 常见原因：检索服务器未启动（Search）、conda 环境未激活 `verl_train_2`、`CUDA_VISIBLE_DEVICES` 指定的 GPU 编号被占用。
